# 求人原稿作成

株式会社Quad が Indeed に掲載する求人原稿を作るためのスキル。
求職者に届き、かつ職業安定法・均等法・労働施策総合推進法に違反しない原稿を出力する。

求人原稿は**広告であると同時に労働条件の明示書類**でもある。読ませる工夫と、
法定記載事項の網羅は両立させる必要があり、後者を落とすと掲載停止や行政指導につながる。
だから「書く」と「検品する」を必ず 2 段階に分ける。

## 進め方

### 1. 情報を集める

`assets/job-posting-template.md` のセクション 0（ヒアリングシート）を読み、
手元の情報で埋まる項目を埋める。会話・既存原稿・企業サイト・過去の求人から拾えるものは拾う。

**埋まらない項目を推測で埋めてはいけない。** 給与や休日を推測で書くと、それは虚偽の労働条件
明示になる（職業安定法 65 条で罰則がある）。原稿中では `{{要確認: 年間休日数}}` の形で
プレースホルダのまま残し、最後に「要確認リスト」としてまとめて返す。

情報が足りなくても**質問だけして止まらない**。確定している範囲で原稿を書き切り、
残りを要確認として示すほうが、依頼者はヒアリングすべき点が具体的に分かって速く進む。

### 2. 原稿を書く

`assets/job-posting-template.md` のセクション 1 の構成をそのまま使う。
節の順序と見出しは変えない — 求職者は媒体をまたいで同じ順序で読むことに慣れており、
順序を崩すと必要な情報にたどり着けなくなる。

文章の作法は `references/writing.md` を読む（文字数の目安、スマホ前提の改行、
職種名の組み立て方、検索語の入れ方、主観形容詞を事実に置き換える手順）。

書くときに効く原則を 3 つだけ先に挙げる。

- **職種名の左 20 文字で決まる。** スマホの検索結果ではそこまでしか表示されない。
  求職者が実際に打ち込む一般名詞（`カスタマーサポート`であって`CS職`ではない）を左に置く。
- **抽象語は情報量ゼロ。** `幅広い業務` `アットホームな職場` は、求職者が自分に
  当てはまるか判断できないので読み飛ばされる。動詞と数字に置き換える
  （`アットホーム` → `平均年齢32歳・20〜30代が7割`）。
- **書けない魅力は作らない。** 実態と違う訴求は、入社後の早期離職という形で企業に返る。
  魅力が薄い求人は、盛るのではなく「誰にとってなら魅力か」を絞る。

### 3. 検品する

`references/legal.md` のチェック表を**全項目**当てる。ここは飛ばさない。
特に落としやすいのは次の 3 つで、いずれも書き忘れがそのまま法令違反になる。

- 固定残業代の 3 点セット（額・相当する時間数・超過分は別途支給する旨）
- 就業場所の変更の範囲／従事すべき業務の変更の範囲（2024/4/1 施行の明示ルール）
- 有期契約の更新上限・無期転換申込機会と転換後の労働条件

続けて `references/writing.md` の掲載品質チェック（1求人1職種、社内造語、使い回しなど）を当てる。

### 4. 返す

この順で出力する。

```
## 求人原稿
（セクション 1 の構成で完成原稿）

## 要確認事項
- 年間休日数：{{要確認}} — 就業規則または人事に確認
- ...

## 法令チェック結果
✅ 12 項目中 10 項目クリア
⚠️ #6 固定残業代：相当時間数が未記載 → 「40,000円（時間外20時間分）」の形に要修正
⚠️ #7 就業場所の変更の範囲：未記載 → 転勤の有無を確認のうえ追記

## 改善提案
- ...
```

チェックに引っかかった項目は、指摘して終わりにせず**直した文面まで示す**。
依頼者が知りたいのは「違反している」ことではなく「どう書けば通るか」なので。

## 既存原稿の添削を頼まれたとき

新規作成と同じ 3 段階を使うが、順序が逆になる。先に検品（ステップ 3）を当てて
違反と欠落を洗い出し、それから文章の改善（ステップ 2 の原則）に進む。

添削では**変更点と理由をセットで示す**。「こう直しました」だけでは依頼者が
次の原稿で同じミスを繰り返すため、`変更前 → 変更後（理由）` の形で並べる。
既に良く書けている箇所は触らない。全面書き換えは依頼者の意図を壊す。
