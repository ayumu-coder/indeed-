## 「職種の定義」と「事業者ごとの実態」を分けている

営業求人で過大表示になりやすいのはここ。会社情報が与えられていないので、
**職種の定義として必ず言えることだけを書き、事業者ごとに違うことは書いていない。**

| 職種 | 定義として書いたこと | 書かなかったこと |
| --- | --- | --- |
| 反響営業 | 「テレアポ・飛び込みはありません」「お問い合わせをいただいた方へのご対応」 | 反響の量、商材 |
| ルート営業 | 「既存のお客様が中心」「担当先が決まっている」 | **「飛び込みなし」** — ルート営業でも新規開拓を含む場合がある |
| 新規開拓営業 | 「最初の接点から担当できる」「提案の型が用意されている」 | **開拓の手法**（反響／紹介／訪問／電話のどれか）。本文では「職場によって違います」と明記 |
| モバイル営業 | 「商材はスマホと通信プラン」「ヒアリングから始まる」 | **販路**（店舗の来店型か法人訪問か）。どちらでも通る文面にしている |

`check.py` の `inbound-only` が、反響営業以外の行で
「テレアポ・飛び込みなし」と断定していないかを機械的に確認している。
初回生成でルート営業のキャッチコピーに「新規の飛び込みはなし」と書いてしまい、
この判定で 5 行弾かれたので差し替えた。

## 書いていないこと（`promise` 判定でブロック）

次の語は 4 列のどこにも出てこない。事業者の実態が未確認のまま書けば
職業安定法 5 条の 3・65 条の虚偽・過大な条件表示になる。

```
ノルマなし / 残業なし / 稼げる / 高収入 / 高待遇 / 必ず / 誰でも / 簡単に
土日休み / 完全週休 / 直行直帰 / 社用車 / フレックス / 転勤なし / 昇給 / 昇格 / 独立 / 即日
```

給与の語（`円` の字を含む）も `wage-word` で全面的にブロックしている。
営業求人は「月給○○万円＋インセンティブ」「年収例」を書きがちだが、
確定した金額を給与欄に入れるまで本文には書かない。

目標・評価については「立て方と仕組みは選考の場でご説明します」としている。
数字の話を避けずに、断定もしない書き方。

## 原稿の作り分け

1 職種 23 行の自由度は `(r, q) = (w % 5, w // 5)` の 2 つだけ。
6 ブロック（導入・問いかけ・業務・ポイント・はじめての方へ・締め）に
`r` / `q` / `(r + k·q) mod 5`（k = 1〜4）という互いに異なる一次式を割り当てると、
同一職種の任意の 2 行で一致するブロックは必ず 1 個以下になる。

職種をまたいで共通のプール（はじめての方へ／締め／向いている方／タイトル接頭辞）は
職種インデックス `j` でさらにずらしている。`j` は職種内では定数なので、
上の「1 個以下」は壊れない。

結果、92 行の相互一致率は**すべて 40% 未満**（`lint_posting.py` の重複判定の閾値は 0.6）。

## 勤務地について

`wards.py` の住所は各区の代表エリアとして**区役所所在地の町名まで**を使っている。
番地は入れていない。実際の勤務地が決まったら差し替えること。
最寄駅も区役所の最寄りとして一般に案内されている駅。
