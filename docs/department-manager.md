# 部長スレッド (全 Claude セッション統括) の運用

ユーザーは原則として「部長 (全スレッド統括)」セッションとだけ会話し、個別スレッドは問題発生時のみ開く。

## 構成

| 要素 | 実体 |
|---|---|
| 部長セッション | tag `dept:manager` を持つセッション (`部長 (全スレッド統括)`) |
| 部下セッション | tag `dept:member` を持つ、ARCHIVED でないセッション |
| 定期パトロール | Routine `部長: 毎時パトロール (部下セッション巡回)`。毎時、部長セッション宛に発火 |
| 部下への指示 | 部下ごとの poke 専用 Routine (`部長→<部下タイトル>`) を `fire_trigger` の `text` で発火 |
| 状態の読み取り | `list_sessions` / `get_session` の `post_turn_summary` (status_category / needs_action) |
| エスカレーション | `PushNotification`。不達時は Slack DM (自分宛) |

## 部長の判断ルール

- blocked / need_input の部下は、部長が答えられる質問なら部長が回答して進める。
- 金額・契約・社名・外部アカウント・不可逆操作 (削除、課金、送信) の承認はユーザーへエスカレーションする。
- `environment_kind = bridge` (Remote Control、ユーザーの Mac 上) のセッションは Mac オフライン時に指示が届かない。失敗ではなく「未達」として扱う。
- 変化がないパトロールでは何も出力しない。

## 部下の追加・除外

- 追加: 対象セッションに `set_session_tags` で `dept:member` を付ける (部長に「このスレッドも見て」と言えばよい)。
- 除外: `dept:member` を remove する。
- 新規の仕事: 部長に依頼すると `create_session` で新設し、同じタグを付ける。

## 制約

- 部下から部長へ直接の返信は届かない。結果は次回パトロール時に読み取る。
- Routine から起動されたターンでは MCP コネクタ (Slack 等) が使えない場合がある。その場合のエスカレーションは `PushNotification` のみ。
- 「ピン止め」の状態は API から取得できないため、初期メンバーは非アーカイブの全セッションとした。不要なものは部長に外させる。
