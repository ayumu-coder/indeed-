# LINE 自動応答くん 第 3 歩 デプロイ手順 (Windows)

対象: 管理シート「LINE自動応答_管理」に紐づく Apps Script プロジェクト。第 2 歩 (commit 6757b1c) が稼働中で、1 分トリガー (`processQueue` / `importDrafts`) が動いている前提。

第 3 歩で入るもの:

- join 時の台帳自動登録 (グループ名を Messaging API で取得し、区分=取引先・有効=TRUE で 1 行追加)
- 手動関数 `registerUnregisteredGroups()` (参加済み・未登録のグループを一括登録)
- 会話ログ末尾の新列「送信者名」(グループ発メッセージの送信者の表示名)

秘密情報 (チャネルアクセストークン等) は従来どおり Script Properties から読みます。この手順で新しく追加する Script Property はありません。

## 1. Code.gs を貼り直す

1. リポジトリの `line-autoreply/gas/Code.gs` をエディタ (メモ帳や VS Code) で開き、全文をコピーする (Ctrl+A → Ctrl+C)。
2. スプレッドシート「LINE自動応答_管理」→ 拡張機能 → Apps Script を開く。
3. 左の「コード.gs」(第 2 歩で貼ったファイル) を開き、中身を全選択して削除し、貼り付ける (Ctrl+A → Ctrl+V)。
4. Ctrl+S で保存する。赤いエラー表示が出ないことを確認する。

## 2. setup を実行する (会話ログに「送信者名」の見出しを足す)

1. エディタ上部の関数選択で `setup` を選び「実行」を押す。
2. 権限の承認ダイアログが出たら許可する。
3. スプレッドシートの「会話ログ」1 行目の末尾 (P 列) に「送信者名」が増え、既存の行と列はそのままであることを確認する。
   「設定」タブに `auto_register_exclude` の行は自動では増えない (既存シートの見出しだけ更新する仕様)。必要なら手で追加する (通常は不要)。

## 3. 「デプロイを管理」で新バージョンを発行する (必須)

Web アプリ (doPost) は「デプロイ」されたバージョンのコードで動くため、貼り直しただけでは反映されません。

1. 右上「デプロイ」→「デプロイを管理」。
2. 現在のデプロイの右の鉛筆 (編集) を押す。
3. 「バージョン」を「新バージョン」にし、説明に「第3歩」などと入れて「デプロイ」。
4. 表示される URL が今までと同じであることを確認する (同じなら LINE Developers の Webhook URL を直す必要はない)。
   「新しいデプロイ」を作ってしまうと URL が変わるので、その場合は Webhook URL を `?token=...` 付きで登録し直す。

1 分トリガー (`processQueue` / `importDrafts`) はエディタに保存された最新コードで動くので、こちらは貼り直しだけで反映されます。トリガーの入れ直しは不要です。

## 4. registerUnregisteredGroups を 1 回実行する

1. 関数選択で `registerUnregisteredGroups` を選び「実行」。
2. 初回は「外部サービスへの接続」の権限承認が出ることがあるので許可する。
3. 「実行ログ」に `N 件中 M 件を台帳へ登録しました` または `未登録のグループはありません` と出る。

## 5. 結果を確認する

「取引先台帳」タブ:

- 未登録だったグループが末尾に増えている。各行は グループID / 会社名=グループ名 / グループ名 / 区分=取引先 / 共有スプレッドシートID・共有フォルダID・担当者=空 / 有効=TRUE / 備考=`自動登録 YYYY-MM-DD HH:mm`。
- 元からあった行は一切変わっていない。
- 【全体連絡用】株式会社Quad (`Cab4b7bb74101992bc1f9efc7d2fc7dde`) は増えていない (コード側で常に除外)。

「稼働ログ」タブ:

- `registerUnregisteredGroups` の INFO 行に、登録したグループ ID と `グループ名「…」` が 1 件ずつ出ている。
- WARN 行があれば、その グループID の会社名が空で登録されている。理由 (`HTTP 404` はボットがそのグループにいない、`HTTP 401` はトークン) を見て、台帳の会社名・グループ名を手で入れる。

「会話ログ」タブ:

- 取引先グループで誰かが発言すると、1〜2 分後に「送信者名」に相手の表示名が入り、状態が `返信案待ち` になる。
- 公式アカウントを新しいグループに追加すると、1〜2 分後に台帳へ行が増え、join 行の処理メモが `自動登録: <グループ名>` になる。

## 6. 手直しを勧めるところ

- 自動登録の「会社名」は LINE のグループ名そのものです。送信前の安全確認は「他社の会社名を含む返信案は送らない」を台帳の会社名で照合するので、グループ名が短い一般語 (「連絡」「打合せ」など) だと他社宛の返信案まで保留になります。会社名列だけ正式な社名に直してください (グループ名列はそのままで構いません)。
- 担当者 (名乗りに使う) は空で登録されます。必要な行だけ入れてください。

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| `registerUnregisteredGroups` で 0 件 | 会話ログにそのグループの行が無い (Webhook 設定前に参加した) → グループで誰かに一言発言してもらってから再実行。または台帳に既にある |
| 会社名が空で登録された | 稼働ログの WARN。`HTTP 404` はボットがそのグループにいない、`HTTP 401` は `LINE_CHANNEL_ACCESS_TOKEN` の失効 |
| 送信者名が入らない | 稼働ログ `senderName` の WARN。相手が公式アカウントを友だち追加しておらず、プロフィール取得に同意していないと 404 になる (LINE の仕様)。10 分後に再取得する |
| 新しいグループに追加しても台帳に増えない | 手順 3 の新バージョン発行を忘れていないか。会話ログに join 行が増えているか (増えていなければ Webhook 側)。除外リストに入っていないか |
| 状態が `エラー` になる | 稼働ログの `processQueue` の ERROR 行に原因が出る |
