# LINE 自動応答くん (第 1 歩: 受信ログ基盤)

取引先との LINE グループのやり取りを自動で返す仕組みを、小さく作って広げていくためのコードです。
この段階では **LINE から届いたイベントを Google スプレッドシートの「会話ログ」に記録し、1 分ごとのトリガーで処理済に変える** ところまでを作ります。返信の生成 (Claude API)・承認フロー・台帳照合は次の段階です。

## 構成

```
line-autoreply/
├── gas/
│   ├── Code.gs          ← Apps Script エディタに丸ごと貼るファイル (自動生成)
│   └── src/entry.js     ← GAS 固有部分の元ソース (doPost / setup / トリガー)
├── lib/                 ← 純粋関数 (Node でテスト可能、GAS にも同じ内容が入る)
│   ├── auth.js          署名検証・Webhook 認証
│   ├── events.js        Webhook ボディの解析、イベント → シート行
│   ├── queue.js         設定の解釈、未処理行の抽出
│   ├── schema.js        シート名・見出しの定義
│   └── time.js          JST 日時整形
├── scripts/build-gas.js ← lib + entry.js を結合して gas/Code.gs を作る
├── test/                ← node --test
└── package.json
```

開発時のコマンド (このディレクトリで実行、依存パッケージなし、Node 22 以上):

```
npm test        # 単体テスト + Code.gs が最新かの検査
npm run build   # lib/ と gas/src/entry.js から gas/Code.gs を再生成
```

`gas/Code.gs` は直接編集しません。`lib/` か `gas/src/entry.js` を直して `npm run build` します。

## 動きの概要

1. LINE が Webhook URL (GAS ウェブアプリ) に POST する。
2. `doPost` がリクエストを認証し、イベントを 1 件 1 行で「会話ログ」に追記して、すぐ `ok` を返す。
   join / leave / memberJoined / memberLeft / follow / postback などメッセージ以外も記録する。
3. 1 分ごとの時間トリガー `processQueue` が「状態=未処理」の行を古い順に最大 50 件取り、
   「処理済」に変えて処理日時を書く (第 1 歩ではここまで)。
4. 動作の記録と異常は「稼働ログ」に残る。

### 重要: 署名検証について

LINE は各リクエストに `X-Line-Signature` ヘッダを付けますが、**Google Apps Script のウェブアプリはリクエストヘッダを `doPost` に渡しません**。そのため GAS 上では署名検証ができません。
`lib/auth.js` の `verifyLineSignature` は署名検証を実装しテスト済みで、ヘッダが取れる環境 (将来の移行先や GAS 側の仕様変更時) では自動的に使われます。GAS ではその代わりに次の 2 つで認証します。

- **Webhook URL の秘密トークン**: `generateWebhookToken()` で作った長いランダム文字列を Webhook URL の末尾に `?token=...` として付け、一致しない要求は記録せず捨てる。
- **destination の照合 (任意)**: スクリプトプロパティ `LINE_BOT_USER_ID` を設定すると、ボディの `destination` (送信先ボットの ID) が一致しない要求も捨てる。

トークン付き URL は LINE Developers コンソール以外には貼らないでください。

### そのほかの安全策

- シートに書く文字列は、先頭が `=` `+` `-` `@` なら数式として解釈されないようアポストロフィを付けます (取引先からの発言で数式注入されないため)。
- 秘密情報はすべてスクリプトプロパティに置き、シートやコードには書きません。
- 「設定」の `mode` が不正・未設定なら安全側の `approval` で動きます。

## スプレッドシートの構成 (`setup()` が作ります)

| シート | 見出し |
| --- | --- |
| 会話ログ | 受信日時, イベント種別, ソース種別, グループID, ユーザーID, メッセージ種別, 本文, replyToken, 状態, webhookEventId, 再送, LINEタイムスタンプ, 処理日時, 処理メモ, 生データ |
| 取引先台帳 | グループID, 会社名, グループ名, 区分 (取引先 / 社内), 共有スプレッドシートID, 共有フォルダID, 担当者, 有効, 備考 |
| 設定 | キー, 値, 説明 (初期行: `mode` = `approval`。`auto` にすると自動送信。今は読み取るだけ) |
| 稼働ログ | 日時, レベル, 処理, グループID, 内容 |

## スクリプトプロパティ (Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」)

| キー | 必須 | 内容 |
| --- | --- | --- |
| `LINE_CHANNEL_SECRET` | 必須 | Messaging API チャネルのチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | 必須 | チャネルアクセストークン (長期)。この段階では未使用だが次の段階の返信に使う |
| `ADMIN_USER_ID` | 必須 | 管理者の LINE ユーザー ID (`U` で始まる)。承認依頼と通知の送り先 |
| `WEBHOOK_TOKEN` | 必須 | `generateWebhookToken()` が自動生成。手で入れる場合は 32 文字以上のランダム文字列 |
| `LINE_BOT_USER_ID` | 任意 | 公式アカウントのボットのユーザー ID (LINE Developers の「チャネル基本設定」に表示される `U` で始まる ID)。設定すると destination 照合が有効 |

値はここには書きません。実際の値は各自の LINE Developers コンソールから取得してください。

## ユーザー作業チェックリスト A: LINE 側の準備

すべて LINE Developers コンソール (https://developers.line.biz/console/) と LINE Official Account Manager で行います。

- [ ] A-1. LINE Developers にログインし、プロバイダーを作成 (既にあればそれを使う)。
- [ ] A-2. プロバイダー内に **Messaging API チャネル** を作成 (既存の LINE 公式アカウントを使う場合は、Official Account Manager の「設定 → Messaging API」から有効化してチャネルに紐づける)。
- [ ] A-3. 「チャネル基本設定」タブで **チャネルシークレット** を控える → スクリプトプロパティ `LINE_CHANNEL_SECRET`。
- [ ] A-4. 同タブの「あなたのユーザーID」(管理者本人の `U...`) を控える → `ADMIN_USER_ID`。
- [ ] A-5. 同タブの「ボットのユーザーID」(公式アカウント側の `U...`) を控える → `LINE_BOT_USER_ID` (任意だが推奨)。
- [ ] A-6. 「Messaging API設定」タブで **チャネルアクセストークン (長期)** を発行して控える → `LINE_CHANNEL_ACCESS_TOKEN`。
- [ ] A-7. 同タブの **応答メッセージ** を「無効」、**あいさつメッセージ** を「無効」にする (Official Account Manager の「応答設定」に飛ぶ)。「Webhook」を「オン」にする。
- [ ] A-8. 「Messaging API設定」タブの **グループトーク・複数人トークへの参加を許可する** をオンにする。
- [ ] A-9. 管理者本人が公式アカウントを **友だち追加** する (QR コードは「Messaging API設定」タブにある)。承認待ちの 1 対 1 通知に必要。
- [ ] A-10. **テスト用の LINE グループ** を作り (管理者 + 動作確認に付き合ってくれる人)、公式アカウントをそのグループに招待する。
- [ ] A-11. Webhook URL の登録は、下の B-8 で GAS の URL ができてから行う。

## ユーザー作業チェックリスト B: スプレッドシートと Apps Script

- [ ] B-1. 運用に使う Google アカウントで **新しいスプレッドシート** を作る (名前の例: `LINE自動応答`)。既存シートに同居させる場合はシート名が衝突しないことを確認する。
- [ ] B-2. メニュー「拡張機能 → Apps Script」を開く。プロジェクト名を付ける。
- [ ] B-3. 既定の `コード.gs` の中身をすべて消し、`gas/Code.gs` の全文を貼り付けて保存する。
- [ ] B-4. 「プロジェクトの設定」(歯車) → 「スクリプト プロパティ」に、上の表のキーを追加する (`WEBHOOK_TOKEN` は B-6 で自動生成されるので入れなくてよい)。
- [ ] B-5. エディタで関数 `setup` を選んで実行する。初回は権限の承認ダイアログが出るので許可する。スプレッドシートに 4 枚のシートができていることを確認する。
- [ ] B-6. 関数 `generateWebhookToken` を実行する。「実行ログ」に `WEBHOOK_TOKEN=...` が出るので、その値を控える (スクリプトプロパティにも自動保存される)。
- [ ] B-7. 関数 `checkConfig` を実行し、実行ログで全キーが「設定済」、全シートが「あり」になっていることを確認する。
- [ ] B-8. 「デプロイ → 新しいデプロイ」→ 種類「ウェブアプリ」→ **次のユーザーとして実行: 自分**、**アクセスできるユーザー: 全員** → デプロイ。表示された **ウェブアプリの URL** (`https://script.google.com/macros/s/.../exec`) を控える。
- [ ] B-9. LINE Developers の「Messaging API設定」→ Webhook URL に、B-8 の URL の末尾へ `?token=` と B-6 の値を付けたものを登録する。
      例: `https://script.google.com/macros/s/XXXX/exec?token=YYYY`
- [ ] B-10. Webhook URL の「検証」ボタンを押す。**成功** と出れば完了。GAS はリダイレクトを挟むため検証ボタンが失敗と表示されることがあるが、その場合も B-12 の実メッセージで確認できれば問題ない (「Webhookの利用」がオンになっていることは必ず確認)。
- [ ] B-11. 関数 `installTrigger` を実行する。「トリガー」(時計アイコン) に `processQueue` の 1 分トリガーが 1 つあることを確認する。
- [ ] B-12. テスト用グループで誰かが発言する。数秒以内に「会話ログ」に行が増え、`状態` が `未処理` になっていることを確認する。
- [ ] B-13. 1〜2 分待ち、その行の `状態` が `処理済`、`処理日時` が入り、「稼働ログ」に `processQueue` の行が出ることを確認する。
- [ ] B-14. 管理者が公式アカウントと 1 対 1 で発言し、`ソース種別=user` の行が増えることを確認する (承認応答の受け口の確認)。

### コードを更新したとき

`gas/Code.gs` を貼り直して保存したあと、「デプロイ → デプロイを管理 → 編集 (鉛筆) → バージョン: 新バージョン → デプロイ」で **同じ URL のまま** 新しいコードを反映します。「新しいデプロイ」を作ると URL が変わり Webhook URL の再登録が必要になります。

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| 会話ログに何も増えない | 「稼働ログ」に `認証失敗: token_mismatch` があれば Webhook URL の `?token=` を確認。何も無ければ LINE 側の Webhook がオフか URL が違う。Apps Script の「実行数」でも `doPost` の実行と失敗が見える |
| `認証失敗: destination_mismatch` | `LINE_BOT_USER_ID` が別チャネルの ID。空にするか正しい値にする |
| `認証失敗: no_signature_and_no_webhook_token` | `WEBHOOK_TOKEN` が未設定。`generateWebhookToken` を実行 |
| `シート「…」がありません` | `setup` を実行していない |
| 状態が未処理のまま | `installTrigger` 未実行。トリガー一覧で `processQueue` の失敗回数も見る |
| 権限エラー | デプロイの「次のユーザーとして実行」が「自分」になっているか。B-5 の承認をやり直す |

## 次の段階 (この README の範囲外)

- 「取引先台帳」でのグループ照合と、台帳にないグループ・社内グループを返信対象外にする処理
- join 時のグループ名による台帳自動紐づけと管理者への確認
- Claude API による返信 JSON の生成 (ナレッジ・直近 30 件・共有シート該当行・共有フォルダ一覧を入力)
- 承認待ちを管理者へ push し、`OK 番号` / `却下 番号` で処理する 1 対 1 フロー
- `mode=auto` での自動送信と、金額・他社名を含む返信の禁止チェック
