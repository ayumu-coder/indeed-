# LINE 自動応答くん (第 1 歩: 受信ログ基盤 / 第 2 歩: 台帳照合・返信案取込・承認・送信 / 第 3 歩: 台帳の自動登録・送信者名)

取引先との LINE グループのやり取りを自動で返す仕組みを、小さく作って広げていくためのコードです。

- **第 1 歩** (commit cf31bb5): LINE から届いたイベントを Google スプレッドシートの「会話ログ」に記録し、1 分ごとのトリガーで処理する。
- **第 2 歩** (commit 6757b1c): 取引先台帳でグループを照合し、返信案を Google Drive 経由で取り込み、管理者へ LINE で承認依頼を送り、『OK 番号』でグループへ送信する。
- **第 3 歩** (この版): 公式アカウントがグループに参加 (join) したら Messaging API でグループ名を取り、取引先台帳へ自動で 1 行追加する。既に参加済みで未登録のグループは `registerUnregisteredGroups()` で一括登録する。グループ発メッセージの送信者名を会話ログの末尾列「送信者名」に記録する。デプロイ手順は [docs/line-autoreply/第3歩デプロイ手順.md](../docs/line-autoreply/第3歩デプロイ手順.md)。

返信案の生成に Anthropic API は使いません。返信案は **Claude Code のセッション (「返信案担当」)** が 1 時間ごとに Google Drive 上へファイルとして置き、GAS がそれを取り込みます。供給元は `gas/src/entry.js` の `collectDraftBatches` 1 か所にまとめてあり、後日 API 方式へ切り替えるときはこの関数だけを差し替えます。

│   ├── approval.js      承認コマンドの解釈、送信前の安全確認、管理者向け本文
│   ├── auth.js          署名検証・Webhook 認証
│   ├── drafts.js        返信案ファイルの解釈、重複排除、取込時の扱い (approval / auto)

│   ├── groups.js        台帳への自動登録行の組み立て、未登録グループの抽出、API 応答 (グループ名 / 表示名) の解釈

├── drafter/
│   └── DRAFTER_PROMPT.txt ← 返信案担当 (Claude Code セッション) に 1 時間ごとに渡す手順書
├── scripts/build-gas.js ← lib + entry.js を結合して gas/Code.gs を作る

開発時のコマンド (このディレクトリで実行、依存パッケージなし、Node 22 以上):

```

npm run build   # lib/ と gas/src/entry.js から gas/Code.gs を再生成
```

`gas/Code.gs` は直接編集しません。`lib/` か `gas/src/entry.js` を直して `npm run build` します。

## 動きの概要

1. LINE が Webhook URL (GAS ウェブアプリ) に POST する。
2. `doPost` がリクエストを認証し、イベントを 1 件 1 行で「会話ログ」に追記して、すぐ `ok` を返す。
   join / leave / memberJoined / memberLeft / follow / postback などメッセージ以外も記録する。
3. 1 分ごとの `processQueue` が「状態=未処理」の行を古い順に最大 50 件取り、**取引先台帳** で振り分ける。
   - グループ発で 区分=取引先 かつ 有効=TRUE のテキスト → 状態「返信案待ち」、処理メモに会社名。
   - 社内 / 未登録 / 無効 / メッセージ以外 / テキスト以外 → 状態「処理済」、処理メモ「対象外 (…)」。
   - 管理者 (`ADMIN_USER_ID`) からの 1 対 1 テキスト → 承認コマンド (`OK 番号` / `却下 番号`) として処理。他人の 1 対 1 は対象外。
   - **(第 3 歩) 台帳に無いグループの join** → `GET /v2/bot/group/{groupId}/summary` でグループ名を取り、取引先台帳に 1 行追加
     (会社名=グループ名, グループ名=グループ名, 区分=取引先, 有効=TRUE, 備考=`自動登録 YYYY-MM-DD HH:mm`, 共有先・担当者は空)。
     処理メモは `自動登録: <グループ名>`。API に失敗しても会社名を空で登録し、稼働ログに WARN を残す。既存行は上書きしない。
     同じバッチ内の後続メッセージは登録後の台帳で振り分けられるので、参加直後の発言もそのまま「返信案待ち」になる。
     leave / memberLeft では何もしない (退会 API は呼ばない)。
   - **(第 3 歩) グループ発の message** → `GET /v2/bot/group/{groupId}/member/{userId}` で表示名を取り、会話ログの末尾列「送信者名」に書く。
     (groupId, userId) ごとに CacheService で 6 時間キャッシュし、失敗は 10 分だけ覚えて連続呼び出しを抑える。振り分け結果には影響しない。
   - 自動登録の対象外: 【全体連絡用】株式会社Quad (`Cab4b7bb74101992bc1f9efc7d2fc7dde`、`lib/schema.js` の `DEFAULT_AUTO_REGISTER_EXCLUDE`) は常に除外。
     「設定」の `auto_register_exclude` にカンマ区切りで ID を書くとさらに除外できる。除外したグループは従来どおり「対象外 (未登録)」。
   - **(第 3 歩) 手動関数 `registerUnregisteredGroups()`**: 会話ログにあって台帳に無いグループ (最後のイベントが leave のものと除外分を除く) を、
     上と同じ処理で一括登録し、登録したグループ ID とグループ名を稼働ログに INFO で残す。何度実行しても既存行は増えない。
4. 返信案担当 (Claude Code セッション、`drafter/DRAFTER_PROMPT.txt`) が 1 時間ごとに「返信案待ち」の行を読み、
   Google Drive の返信案フォルダに `LINE返信案_YYYYMMDD-HHMM` (スプレッドシート or CSV) を置く。
5. 1 分ごとの `importDrafts` が未取込ファイルを「返信案」タブへ取り込み (webhookEventId で重複排除、ファイル ID を「取込済」に記録)、
   - 判定=返信 → 状態「承認待ち」、管理者へ `案 #番号【会社名】 受信: … 返信案: … → 送るなら『OK 番号』、送らないなら『却下 番号』` を push。
   - 判定=人に回す → 状態「人に回す」、管理者へ `人に回す #番号【会社名】 受信: … 理由: …` を push (OK/却下 は受け付けない)。
   - 会話ログに送信者名があれば、どちらも `受信 (送信者名): …` になる (第 3 歩)。
   - 設定 `mode=auto` のときは、判定=返信 で安全確認を通ったものを承認なしでグループへ送る。通らなければ「送信保留」。
6. 管理者が `OK 番号` → **送信前の安全確認** (本文に「円」「¥」「万円」が無い / 台帳の他社名を含まない / 送信先が 区分=取引先 かつ 有効) を通ればグループへ push。
   成功 → 返信案「送信済」+ 会話ログ「返信済」。失敗 → 「送信失敗」+ 送信結果にエラー。安全確認に引っかかれば「送信保留」+ 管理者へ理由。
   `却下 番号` → 「却下」。番号が無い・状態が「承認待ち」でない → 管理者へ「該当なし」。
7. 取込・承認・送信・保留・エラーはすべて「稼働ログ」に残る (トークン等の秘密情報は書かない)。

### 状態の一覧

| 会話ログの状態 | 意味 |
| --- | --- |
| 未処理 | 受信直後 |
| 返信案待ち | 取引先からのテキスト。返信案担当が返信案を書くのを待っている |
| 承認待ち | 返信案を取り込み、管理者の OK/却下 待ち |
| 人に回す | 返信案担当が人に回すと判定した、または安全確認で送信保留になった |
| 返信済 | グループへ送信した |
| 処理済 | 対象外、または 却下 |
| エラー | 送信失敗や処理失敗 |

| 返信案タブの状態 | 意味 |
| --- | --- |
| 承認待ち | `OK 番号` / `却下 番号` を受け付ける唯一の状態 |
| 人に回す / 送信保留 / 却下 / 送信済 / 送信失敗 | それぞれの結果。OK/却下 は受け付けない |

### 重要: 署名検証について

LINE は各リクエストに `X-Line-Signature` ヘッダを付けますが、**Google Apps Script のウェブアプリはリクエストヘッダを `doPost` に渡しません**。そのため GAS 上では署名検証ができません。
`lib/auth.js` の `verifyLineSignature` は署名検証を実装しテスト済みで、ヘッダが取れる環境 (将来の移行先や GAS 側の仕様変更時) では自動的に使われます。GAS ではその代わりに次の 2 つで認証します。

- **Webhook URL の秘密トークン**: `generateWebhookToken()` で作った長いランダム文字列を Webhook URL の末尾に `?token=...` として付け、一致しない要求は記録せず捨てる。
- **destination の照合 (任意)**: スクリプトプロパティ `LINE_BOT_USER_ID` を設定すると、ボディの `destination` (送信先ボットの ID) が一致しない要求も捨てる。

トークン付き URL は LINE Developers コンソール以外には貼らないでください。

### そのほかの安全策

- シートに書く文字列は、先頭が `=` `+` `-` `@` なら数式として解釈されないようアポストロフィを付けます (取引先からの発言で数式注入されないため)。
- 秘密情報はすべてスクリプトプロパティに置き、シートやコードには書きません。
- 「設定」の `mode` が不正・未設定なら安全側の `approval` で動きます。
- グループへ送るのは「管理者が OK した」か「`mode=auto` で安全確認を通った」ときだけで、どちらも送信直前に `checkSendSafety` を通します。社内グループ・台帳未登録・無効のグループへは送りません。
  自動登録された行も 区分=取引先 かつ 有効=TRUE なので送信対象です。会社名が空でも送信は止めません (安全確認の条件は第 2 歩から変えていません)。
- 承認コマンドは `ADMIN_USER_ID` からの 1 対 1 メッセージだけを受け付けます。
- 第 3 歩で呼ぶ Messaging API は取得系 (`group/{id}/summary`, `group/{id}/member/{userId}`) だけです。退会 (`leave`) API は呼びません。グループ宛の送信は従来どおり `importDrafts` → `checkSendSafety` を通る経路だけです。
- 自動登録の「会社名」はグループ名そのものです。安全確認の「他社名を含まない」はこの会社名で照合するので、グループ名が短い一般語 (例: 「連絡」「打合せ」) だと他社宛の返信案が保留になりやすくなります。台帳の会社名を正式な社名に手で直すことを勧めます (グループ名列はそのままでよい)。

## スプレッドシートの構成 (`setup()` が作ります)

| シート | 見出し |
| --- | --- |
| 会話ログ | 受信日時, イベント種別, ソース種別, グループID, ユーザーID, メッセージ種別, 本文, replyToken, 状態, webhookEventId, 再送, LINEタイムスタンプ, 処理日時, 処理メモ, 生データ, **送信者名** (第 3 歩で末尾に追加。第 1 歩からの並びは変えていない。列は見出し名で引く) |
| 取引先台帳 | グループID, 会社名, グループ名, 区分 (取引先 / 社内), 共有スプレッドシートID, 共有フォルダID, 担当者, 有効 (チェックボックスまたは TRUE), 備考 (自動登録なら `自動登録 YYYY-MM-DD HH:mm`) |
| 設定 | キー, 値, 説明 (初期行: `mode` = `approval`。`auto` にすると安全確認を通った返信案を承認なしで送る。`auto_register_exclude` = 自動登録しないグループID をカンマ区切り、空でよい) |
| 稼働ログ | 日時, レベル, 処理, グループID, 内容 |
| 返信案 | 番号, webhookEventId, グループID, 会社名, 受信本文, 返信案, 判定, 理由, 状態, 作成日時, 承認日時, 送信結果, 取込元 |
| 取込済 | ファイルID, ファイル名, 取込日時, 取込件数, 重複件数, 備考 |

返信案担当が置くファイル (`LINE返信案_YYYYMMDD-HHMM`) の 1 行目は `webhookEventId, グループID, 会社名, 受信本文, 返信案, 判定 (返信 / 人に回す), 理由` です。列は見出し名で引くので順序は問いません。

## スクリプトプロパティ (Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」)

| キー | 必須 | 内容 |
| --- | --- | --- |
| `LINE_CHANNEL_SECRET` | 必須 | Messaging API チャネルのチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | 必須 | チャネルアクセストークン (長期)。管理者への push とグループへの送信に使う |
| `ADMIN_USER_ID` | 必須 | 管理者の LINE ユーザー ID (`U` で始まる)。承認依頼と通知の送り先 |
| `WEBHOOK_TOKEN` | 必須 | `generateWebhookToken()` が自動生成。手で入れる場合は 32 文字以上のランダム文字列 |
| `LINE_BOT_USER_ID` | 任意 | 公式アカウントのボットのユーザー ID (LINE Developers の「チャネル基本設定」に表示される `U` で始まる ID)。設定すると destination 照合が有効 |
| `DRAFT_FOLDER_ID` | 必須 (第 2 歩) | 返信案担当がファイルを置く Google Drive フォルダの ID (URL の `folders/` の後ろ) |

値はここには書きません。実際の値は各自の LINE Developers コンソールから取得してください。

## うまくいかないとき

| 症状 | 見るところ |
| --- | --- |
| 会話ログに何も増えない | 「稼働ログ」に `認証失敗: token_mismatch` があれば Webhook URL の `?token=` を確認。何も無ければ LINE 側の Webhook がオフか URL が違う。Apps Script の「実行数」でも `doPost` の実行と失敗が見える |
| `認証失敗: destination_mismatch` | `LINE_BOT_USER_ID` が別チャネルの ID。空にするか正しい値にする |
| `認証失敗: no_signature_and_no_webhook_token` | `WEBHOOK_TOKEN` が未設定。`generateWebhookToken` を実行 |
| `シート「…」がありません` | `setup` を実行していない |
| 状態が未処理のまま | `installTrigger` 未実行。トリガー一覧で `processQueue` の失敗回数も見る |
| 権限エラー | デプロイの「次のユーザーとして実行」が「自分」になっているか。B-5 / C-4 の承認をやり直す |
| 返信案待ちのまま増えない | 返信案担当の Routine が動いていない、またはフォルダ ID が違う。稼働ログの `importDrafts` の WARN/ERROR を見る |
| 返信案ファイルを置いたのに取り込まれない | ファイル名が `LINE返信案_YYYYMMDD-HHMM` で始まっているか、形式が Google スプレッドシートか CSV か、「取込済」に既に記録されていないか。1 行目の見出しが不備なら「取込済」の備考に理由が入る |
| `OK 1` に「該当なし」と返る | 「返信案」タブの #1 の状態が `承認待ち` 以外 (送信済 / 人に回す / 送信保留 など) |
| `送信保留` になる | 返信案に「円」「¥」「万円」か他社名が含まれる、または送信先が台帳で 取引先 / 有効 でない。理由は管理者への通知と「送信結果」列にある |
| `送信失敗 HTTP 4xx` | `LINE_CHANNEL_ACCESS_TOKEN` が失効・誤り (401)、ボットがグループにいない (400/403)。稼働ログの `send` 行に応答本文の先頭が残る |
| 自動登録の会社名が空 | 稼働ログの `processQueue` / `registerUnregisteredGroups` の WARN に理由 (`HTTP 404` はボットがそのグループにいない、`HTTP 401` はトークン)。台帳の会社名・グループ名を手で入れれば以後はそのまま使われる |
| 送信者名が空 | 稼働ログの `senderName` の WARN を見る。相手が公式アカウントを友だち追加していない・プロフィール取得に同意していない場合は 404 になり取得できない (LINE の仕様)。10 分後に再取得する |
| 参加済みなのに台帳に増えない | `registerUnregisteredGroups` を実行したか。会話ログにそのグループの行が 1 件も無い (Webhook 設定前に参加した) 場合は、グループで誰かに発言してもらって行を作ってから再実行する。除外リスト (全体連絡用 / `auto_register_exclude`) に入っていないか |

## 次の段階 (この README の範囲外)

- 自動登録した行の会社名を管理者に確認してもらう仕組み (今はグループ名がそのまま会社名になる)
- 返信案担当への入力の拡充 (ナレッジ・共有スプレッドシート該当行・共有フォルダ一覧)
- 返信案の供給元を API 方式へ切り替える (`collectDraftBatches` の差し替え)
- 承認待ちが長時間放置されたときの再通知
